# 标定阶段详解

> 标定是整个工作流的根基，标定误差会被后续每一步放大。**这一步多花时间是值得的**。

## 一、为什么要做联合标定

Kinect v2 是**两个独立的相机**：

| 相机 | 位置 | 分辨率 | 视场角 |
|---|---|---|---|
| 彩色相机 (RGB) | 设备左侧 | 1920×1080 | 84° × 54° |
| 深度相机 (IR) | 设备右侧 | 512×424 | 70° × 60° |

两个相机之间物理距离约 52mm。同一时刻拍的两张图，**像素根本不对应**。要把深度图的颜色信息对齐到彩色图（或反过来），必须知道：

1. **RGB 内参**（焦距、主点、畸变）
2. **IR 内参**（同上）
3. **两相机之间的相对位姿**（R 旋转、T 平移）

Kinect v2 SDK 自带的 `MapDepthFrameToColorSpace` 用**出厂默认参数**，每台设备实际略有不同。**自己标定一次能把对齐误差从 1-2cm 降到亚毫米级**。

## 二、张正友标定法的核心

张正友 2000 年发表的 [《A flexible new technique for camera calibration》](https://www.microsoft.com/en-us/research/publication/a-flexible-new-technique-for-camera-calibration/)，是 OpenCV `calibrateCamera` 的算法基础。

**核心思想**（一句话版）：让相机从不同姿态观察一个平面棋盘，利用每个姿态下"棋盘平面→图像平面"的单应矩阵 H 来反推内参 K，最后非线性优化精化。

**数学推导**（简略）：

棋盘上一个角点 `M = [X, Y, 0, 1]ᵀ`（Z=0 是因为棋盘是平面），在图像上的位置 `m = [u, v, 1]ᵀ`：

```
s·m = K [R₁ R₂ R₃ t] M = K [R₁ R₂ t] [X, Y, 1]ᵀ
```

因为 Z=0，第三列 R₃ 被消掉。所以 **H = K [R₁ R₂ t]** 是 3×3 单应矩阵。

R₁、R₂ 是正交单位向量，可推出关于 K 的两个约束：

```
h₁ᵀ K⁻ᵀK⁻¹ h₂ = 0                     # R₁ ⊥ R₂
h₁ᵀ K⁻ᵀK⁻¹ h₁ = h₂ᵀ K⁻ᵀK⁻¹ h₂          # |R₁| = |R₂|
```

令 B = K⁻ᵀ K⁻¹（6 个未知数），每张图给 2 个方程。N 张图 → 2N 个方程 → SVD 解 B → Cholesky 得 K → LM 优化所有外参 + 畸变 + K。

**立体标定**：在 N 张同步拍摄的图上，分别求出 RGB 和 IR 看到棋盘的外参 [R_c, t_c] 和 [R_d, t_d]，两相机间的关系：

```
R = R_c · R_d⁻¹       # IR → RGB 的旋转
T = t_c - R · t_d     # IR → RGB 的平移
```

OpenCV 的 `cv2.stereoCalibrate` 在多张图上做最小二乘 + LM 优化得到统一的 R, T。

## 三、Step 1: 准备棋盘

**棋盘要求**：

- **7×6 内角点**（即 8×7 个方格）
  - "内角点" 是棋盘内部的黑白交叉点，不是外周角
  - 7×6 = 42 个角点，每张图提供 84 个约束
- **格边长 25mm**（精确测量，填入 `--square` 参数）
- **平面性**：贴在硬纸板/铝板上，**纸张柔性变形会让标定精度大打折扣**
- **哑光打印**：亮面会反光过曝，IR 图上角点会消失

**自查**：尺子量几个格子，应该都是 25mm ± 0.5mm。如果差异超过 1mm 重新打印。

## 四、Step 2: 同步采集棋盘对

```bash
python 01_capture_calib.py --output calib_imgs --pattern 7x6
```

**操作流程**：

1. 启动 Kinect，把棋盘举在前方
2. 实时检测：
   - **绿色十字** = 当前位置 RGB 和 IR 都检测到
   - **黄色提示** = 只 RGB 检测到（IR 端可能太暗/太斜）
   - **红色提示** = 都没检测到
3. **等画面静止 1 秒**（防抖）+ 双方都检测到 + 按 SPACE 保存
4. 调整棋盘位置/姿态，重复

**拍摄策略**（共 50-60 对）：

| 距离档 | 数量 | 用途 |
|---|---|---|
| 0.8m | 12-15 对 | 标定近处畸变 |
| 1.2m | 12-15 对 | 中等距离 |
| 1.6m | 12-15 对 | 接近物体扫描距离 |
| 2.0m | 12-15 对 | 远处畸变 |

每档内**姿态多样化**：
- 正面、左倾、右倾、上仰、下俯
- 棋盘旋转 0°、45°、90°
- 中心、左上、右下等不同画面位置

**关键技巧**：

- **不需要外加 IR 光源**：靠 SB 算法 + CLAHE 预处理处理散斑
- **不需要盖 IR 投射器**：默认散斑能容忍
- 但如果 IR 检测成功率 < 50%，加一个 LED 强光手电从侧面照棋盘

## 五、Step 3: 联合标定

```bash
python 02_calibrate.py --input calib_imgs --pattern 7x6 --square 25
```

**输出文件**：`calib_imgs/calibration.json`

**程序会做的事**：

1. 在每对图上检测 RGB 和 IR 角点（用 OpenCV `findChessboardCornersSB`）
2. 只保留双方都检测到的对（通常 65-80%）
3. RGB 内参标定（`cv2.calibrateCamera`）
4. IR 内参标定（同上）
5. 立体标定（`cv2.stereoCalibrate` + `CALIB_FIX_INTRINSIC` 锁定内参不变）

## 六、Step 4: 验证标定质量

**判断标准**：

| 指标 | 数值 | 评价 |
|---|---|---|
| RGB RMS | < 0.3 px | 优秀 |
| RGB RMS | 0.3 - 0.5 px | 很好 |
| RGB RMS | 0.5 - 1.0 px | 可用 |
| RGB RMS | > 1.0 px | 重做 |
| IR RMS | < 0.5 px | 优秀（散斑环境下） |
| IR RMS | 0.5 - 0.8 px | 很好 |
| IR RMS | 0.8 - 1.2 px | 可用 |
| IR RMS | > 1.2 px | 重做 |
| Stereo RMS | < 0.8 px | 优秀 |
| Stereo RMS | 0.8 - 1.5 px | 可用 |
| Stereo RMS | > 1.5 px | 重做 |

**外参检查**：

- T (mm) 应接近 **[-52, 0, 0]**（Kinect 出厂物理布局）
  - T_x 在 [-55, -49] 是正常
  - T_y、T_z 在 [-5, 5] 是正常
  - 超过这个范围说明立体标定出错了
- R 旋转应接近 [0, 0, 0]，几度内是正常

## 七、常见标定失败原因

**RGB 角点检测成功率高，IR 失败率高**

→ 拍摄时 IR 端因为散斑/亮度不够。调整：
- 增加环境光（开多盏灯，靠窗户）
- 棋盘举近一些（最远 1.5m 内）
- 棋盘表面是不是反光？换哑光打印

**双方成功率都低**

→ 棋盘问题：
- 平面性差（贴硬板）
- 太斜（角度 > 60°）
- 太远（> 2m）
- 太小（占画面 < 1/4）

**RMS 偏高（> 1px）**

→ 角点检测精度不够：
- 检查棋盘是否折损
- 拍摄时是不是抖了？等画面静止再按 SPACE
- 添加更多近距离样本

**立体 RMS 偏高**

→ 单相机内参就有问题，或者同步对不够：
- 看 RGB/IR 单独标定的 RMS，谁高谁就是元凶
- 同步对至少要 30 对有效
- 棋盘有没有 "扭曲" 一样？柔性变形会让两个相机看到不同形状

## 八、为什么不用 ROS 的 iai_kinect2 之类的现成工具

如果你能用，强烈推荐用。但 iai_kinect2 依赖 ROS + Ubuntu。我们这套是纯 Python + Windows，跑在你现有的环境。

精度上没差距——核心算法都是 `cv2.calibrateCamera` + `cv2.stereoCalibrate`，是同一套数学。

## 九、标定结果可长期复用

`calibration.json` 保存了相机的"出厂参数"，**只要你不拆 Kinect、不摔、不换机**，这份标定可以用一年甚至更久。

但如果：
- 设备摔过/换过 → 重新标定
- 长时间未用（半年+） → 验证一下，最好重做
- 换了相机姿态/支架 → 不影响（外参是 Kinect 内部的）
- 换扫描对象 → 不影响
